# 专业子文件填写说明（人读版）

`majors/_template/SKILL.md` 是机器可复制的骨架，本文说明每一段**到底要写什么**、以及校验脚本会检查什么。

## 九段各自的作用

| 段 | 作用 | 常见写坏的方式 |
|---|---|---|
| 1 这个专业在训练什么 | 给模型一个"能力画像"，决定它举例时往哪个方向靠 | 抄培养方案（"培养德智体美劳全面发展"），等于没说 |
| 2 课程地图 | 让用户看到全景，也让模型知道"这门课在整条链上的位置" | 只列课名，不标先修、不说哪门最陡 |
| 3 能力目标 | 毕业时的可检验产出，是路径的"终点定义" | 写"具备扎实的理论基础"——不可检验 |
| 4 知识点表 | 本文件的核心数据结构，进度、路径、判级全靠它 | 行数不够 20；前置留空导致没有坡度；难度乱标 |
| 5 术语与符号 | 让回答"像本专业的人说的" | 抄词典定义；漏掉参考方向、下标起点这类真正的坑 |
| 6 题型套路 | `solve` 模式直接调用 | 每类只写"认真审题"；不给步骤骨架 |
| 7 常见误区 | 提前拦住高频错误 | 写"要细心""多练习" |
| 8 教材 | 给用户一个可继续的入口 | 编 ISBN/版次/页码 |
| 9 交叉与去向 | 回答"我和隔壁专业有什么区别" | 只写岗位名，不写区别 |

## 知识点表怎么写才算好

```markdown
| K02-3 | 链表操作与边界处理 | L2 | K02-1 | 能不看资料写出插入/删除/就地逆置，覆盖空表、单结点、头尾 | 90min |
```

四个字段的判断标准：

- **难度**：换个数还会做 → `L1`；换个问法还能找到入口 → `L2`；换个场景知道该建什么模型 → `L3`。
- **前置**：写"不会它就无法开始"的点，不写"相关"的点。前置太多会让路径变窄。
- **过关标准**：第三人能独立判断过没过。`能 + 动作 + 可观察结果`。
- **预计**：`L1` 40–60min，`L2` 60–90min，`L3` 90–150min。

## 校验脚本会查什么

`python tools/validate.py` 对每个专业检查：

1. 文件存在、frontmatter 的 `name` 等于 `major-<目录名>`、`description` 长度 ≥ 60；
2. 九个编号章节齐全；
3. 知识点行数 ≥ 20，ID 不重复，名称非空；
4. 难度只能 `L1/L2/L3`；
5. 前置 ID 必须存在于同表；
6. 先修图无环；
7. 至少一个无前置的 `L1` 入口（否则警告）；
8. 先修链最深 ≥ 3 层（否则警告）；
9. 全文 ≤ 300 行；
10. 没有 `TODO` / `待补` / 占位符。

## 写作语气

参照 `majors/computer-science/SKILL.md`：**短句、给因果、不说套话**。

- ❌「在学习过程中，学生应当注重培养自身的逻辑思维能力。」
- ✅「卡住时先画出调用栈，不要盯着代码看。」

## 一个自检问题

写完问自己一句：**如果一个学弟拿着这份文件自学，他能不能在第一天就知道该点开哪个知识点？**

不能，说明第 2 段或第 4 段的入口点有问题。
