# 课程与路径规则（Curriculum Rules）

> 全仓库共用一套规则。改规则要改这个文件，不要各专业自己发明。
> 这些规则的存在理由只有一个：让"从简到难"变成**可执行、可检查**的东西，而不是感觉。

## 1. 结构：模块与知识点

每个专业的课程地图拆成 **4–8 个模块（K01…K08）**，每个模块下 **3–6 个知识点**，全专业 **≥ 20 个知识点**。

- 模块 = 一门课或一个成体系的能力块（如「数据结构」「操作系统」）。
- 知识点 = 一次能学完、能测的最小单元（40–150 分钟的量）。
- ID 格式：模块 `K03`，知识点 `K03-2`。**ID 一旦发布不要改**，用户进度文件按 ID 索引。

知识点表固定六列：`ID | 名称 | 难度 | 前置 | 过关标准 | 预计投入`。

## 2. 难度三档（L1 / L2 / L3）

判定标准看**解题时需要同时握住几个东西**，不看"看起来难不难"。

| 档 | 定义 | 长什么样 | 跨学科例子 |
|---|---|---|---|
| `L1` 入门 | 单一概念 + 直接套用；错多半是记错或算错 | 套公式、写定义、认符号 | 求导；写出一条 SQL；背出胃的四个分区；给单词标音标 |
| `L2` 进阶 | 两个以上概念组合；需要**选择**用哪个工具；错多半是选错方法 | 综合题、多步计算、条件分类讨论 | 用洛必达+泰勒求极限；判断死锁并给银行家算法分配；鉴别诊断两个相似病；给电路列节点方程 |
| `L3` 挑战 | 需要建模、构造、证明或处理开放条件；错多半是**没想到** | 证明题、设计题、优化、误差分析、开放论述 | ε-δ 证明；设计 O(n) 算法并证明下界；给不确定度做误差传播；设计一个对照实验；写一份可辩护的政策建议 |

**自检口诀**：换个数还会做 → L1；换个问法还能找到入口 → L2；换个场景知道该建什么模型 → L3。

## 3. 先修关系（前置图）

- 每个知识点写 `前置:`，可以空（表示入口点），可以有多个。
- 前置必须**真实存在**（ID 在同表内），且**图无环**。有环说明拆错了，宁可拆细。
- 跨课程前置要写课程名缩写，如 `前置: K03-2（数据结构·树）`。
- 一个专业至少有 **1 条 3 层深的链**（A→B→C），否则说明拆得太平，学起来没有坡度。

## 4. "从简到难"的可执行定义（排序算法）

给定一个专业的全部知识点，按下面三步排出唯一顺序。**不要凭直觉排序**，否则同一个用户两次问会拿到两条不同的路。

1. **按难度分带**：所有 `L1` 在前，再 `L2`，再 `L3`。理由：先让用户拿到"我能学会"的反馈，再上组合。
2. **带内按拓扑序**：同难度带内，前置必须先出现。若出现"L1 依赖 L3"这种反常，说明难度标注错了，回去改标注而不是改顺序。
3. **同层按被依赖次数降序**：被后续知识点引用越多的越先学（它是地基）。次数相同按 ID 升序，保证确定性。

如果拓扑序和难度带冲突（前置难度更高），**以拓扑序为准**，并在路径表里标 `⚠ 前置较难`——诚实比好看重要。

## 5. 跳级规则

用户想直接学一个前置未满足的点：

1. 先出 **3 道前置抽查题**（针对紧邻的前置点，L1/L2 混合，判断"够不够用"而不是"学没学过"）。
2. 全对 → 放行，进度文件记 `override`，写清原因。
3. 错 1 题及以上 → 先补那 1 个前置点，补完再回来。**不要**因为用户着急就跳过。
4. 用户明确说"我就是想先看看这个" → 可以讲，但开头一句说明"这里会用到一个你还没学的前置 X，我先把 X 的最小必要部分讲 3 分钟"，讲完再进正题。

## 6. 过关标准怎么写

过关标准是**验收**，不是感想。必须能被第三个人独立判断"过没过"。

- ✅ 好：`能不看资料写出单链表插入/删除，并覆盖头插、尾插、空表三个边界`
- ✅ 好：`给定一组血常规，能说出最可能的 2 个诊断方向及各自的支持/反对证据`
- ✅ 好：`能对任意给定的分段函数判断连续性，并写出理由`
- ❌ 坏：`理解链表`、`掌握诊断思路`、`熟悉公式`
- ❌ 坏：`多做题`、`认真听讲`

**模板**：`能（在什么条件下）（做什么动作）（达到什么可观察结果）`。

## 7. 学习目标怎么写

每个知识点开头一句 `学完你能：…`，一条目标含**一个动词 + 一个可观察产物**：

- 解出 / 推出 / 画出 / 写出 / 跑通 / 判断出 / 估算出 / 设计出 / 说清
- 产物要具体：一段证明、一张图、一份表、一段能跑的代码、一个诊断结论

不要写"了解 XX 的背景"——除非背景本身就是考点。

## 8. 课时估算

| 难度 | 单点预计投入 | 说明 |
|---|---|---|
| L1 | 40–60 分钟 | 含 2 道自测 |
| L2 | 60–90 分钟 | 含 1 道综合 |
| L3 | 90–150 分钟 | 含 1 次完整推导或设计 |

路径总时长 = 各点之和，输出时给区间（±20%），不要给"精确到分钟"的假精度。例：`约 18–22 小时（按每天 1 小时算，3 周）`。

## 9. 路径表输出模板

`roadmap` 模式固定用这张表 + 三个里程碑，不要自由发挥：

```
阶段 | 模块 | 知识点 | 难度 | 前置 | 过关标志 | 预计
-----|------|--------|------|------|----------|------
     |      |        |      |      |          |
```

表后必须给：

1. **三个里程碑**（不是"学完第一阶段"，而是可交付物）：
   `M1 你就能独立解出 XX 类题` / `M2 你就能读懂 XX 教材的第三章并做课后题` / `M3 你就能完成一个 XX 小项目或通过 XX 类考试`
2. **一句总时长 + 建议节奏**（如"每天 1 小时，约 3 周"）。
3. **一个"最小可行起点"**：如果用户只有 20 分钟，先学哪一个点、为什么。

## 10. 间隔复习（必做，不占课时）

每推进 **3 个新知识点**，插入 1 道**前面已学知识点**的回炉题（优先挑 `struggling` 里的）。理由：不做间隔复习，用户在第 8 个点就会开始忘第 2 个点，然后误以为"我不适合学这个"。

回炉题只出 1 道，答完就给结论（过了 / 需要回补），不要演变成小测验。

## 11. 与"解题"模式的关系

`learn` 负责"建立"，`solve` 负责"调用"。

- 用户在 `learn` 里问一道题 → 转 `solve`，但默认仍走脚手架（先给地图）；如果这题正是当前知识点的例题，直接按例题讲。
- 用户在 `solve` 里反复错同一类 → 退回去 `learn` 那个知识点，并记 `struggling`。
- **判据**：错在"没想到方法"→ 回 `learn`；错在"算错/写错"→ 留在 `solve`，练手稳度。
