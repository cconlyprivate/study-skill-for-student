# 定级流程（Diagnosis）

> 目的：不靠"我觉得你应该是零基础"这种猜测决定起点。**先问，再测，再判，最后让用户点头。**
> 全程预算 3–5 分钟。超过 5 分钟，用户会觉得"我在做卷子"而不是"我在学东西"。

## 第一步：问基础（必须停下等回答）

用编号列表问，句子短，给出退出选项：

```
先确认一下你的基础，回个数字就行：
1) 完全零基础 / 刚接触
2) 学过一部分，但说不清自己什么水平
3) 学过，想复习巩固 / 冲刺
4) 我上过这门课但基本忘了

（说不清也没关系，选 2 我来测）
```

**必须停下来等用户回答。** 不许自己替用户选，不许写"如果你选 2 那么我就……"然后接着讲。

## 第二步：按选择分支

### 选 1（零基础）或 4（基本忘了）
- 起点 = 该专业路径里第一个 `L1` 知识点。
- 补问一句目标（`考试 / 绩点 / 项目 / 转专业 / 兴趣`），写进 `profile.goal`。目标不同，例题选材不同。
- 不测。零基础的人被出题会更焦虑，收益为零。

### 选 3（复习巩固）
- 从该专业「课程地图」里给编号列表（只列模块，不列知识点），让用户勾"学过的课"。
- 在勾选范围内出 **2 道抽查题**：1 道 `L2` + 1 道 `L3`。目的不是判级，是确认"哪块真的还在"。
- 起点 = **第一个未掌握模块的第一个 `L1` 点**（跳过已勾选且抽查通过的部分）。
- 抽查全过 → 起点直接给到 `L3` 综合模块，路径压缩成「查漏清单 + 真题」。

### 选 2（说不清）→ 进第三步

## 第三步：出 5 道分级诊断题

### 出题规格（逐条照做）

1. **5 道，固定配比**：`L1 × 1`、`L2 × 2`、`L3 × 1`、`综合应用 × 1`。
2. **必须来自 4 个以上不同模块**。5 道全落在第一章，测出来的是"你学没学过第一章"，不是水平。
3. 每题 **4 个选项**，只有一个正确；不要"以上都对/都不对"这种低区分度选项。
4. 选项设计要能暴露典型误解：把最常见的错法放进干扰项（这样判错时能说清错在哪）。
5. 只标 `A/B/C/D`，**不标难度、不给提示、不夹解析**。
6. 一次把 5 题列完，然后**停**。等用户一次性回 `1B 2C 3A 4D 5B` 这种就行。
7. 题面控制在 3 行内。需要大段材料的题不适合做诊断。

### 示例（计算机科学与技术，只示范格式，不要照抄到别的专业）

```
1. 下列时间复杂度按从小到大排列正确的一组是：
   A. O(n) < O(log n) < O(n log n)
   B. O(log n) < O(n) < O(n log n)
   C. O(n log n) < O(n) < O(log n)
   D. O(log n) < O(n log n) < O(n)

2. 对 8 个元素的有序数组做二分查找，最多需要比较几次？
   A. 2    B. 3    C. 4    D. 8

3. 循环队列用长度为 n 的数组实现，采用"牺牲一个单元"的方式判满，队满条件是：
   A. front == rear
   B. (rear + 1) % n == front
   C. rear == n - 1
   D. front == 0 && rear == n - 1

4. 在 n 个顶点、e 条边的无向连通图上做 BFS，时间复杂度是：
   A. O(n)    B. O(e)    C. O(n + e)    D. O(n * e)

5. 一个进程从"运行态"出发，下列转移不可能直接发生的是：
   A. 运行 → 就绪      B. 运行 → 阻塞
   C. 运行 → 终止      D. 阻塞 → 运行
```

（答案：1B 2C 3B 4C 5D；第 5 题 D 是经典陷阱——阻塞态必须先回就绪态。）

### 判分（用户答完才做）

逐题输出三行：`对/错`、`正确答案`、`一句解析（重点讲那个错误选项为什么诱人）`。**不要只报分数。**

## 第四步：判级

| 命中 | 档位 | 起点 | 路径形态 |
|---|---|---|---|
| 0–1 | `L1` 入门 | 第 1 个知识点 | 完整路径，不跳步；每个 L1 点都配一个"最小可运行例子" |
| 2–3 | `L2` 进阶 | 核心课里第一个 `L2` 知识点，**先过 L1 前置抽查** | L1 压缩成「速览 + 自测」，主攻 L2 |
| 4–5 | `L3` 挑战 | 综合应用模块 | 查漏清单 + 综合题/项目为主，L1 只在出错时回补 |

判级要说清依据，一句话即可：`你在第 3、5 题上踩了典型坑（队列判满、阻塞态转移），说明基础概念有缺口，判 L2 进阶。`

## 第五步：确认（不可跳过）

必须原样问一句：

```
我判断你在 L2 进阶，起点是 K03-1（栈与队列），要不要调整？
```

用户点头后，才写进度文件（格式见 `progress-schema.md`），并在回复里展示写入结果（专业、档位、起点、目标）。

用户说"太高了/太低了" → 按用户说的调，并在 `override` 里记一句原因。**用户的自我判断优先于测试结果**——他可能刚复习过，也可能当天状态差。

## 常见错误

- ❌ **自问自答**：出完题自己接"假设你选 B，那么……"。这让整个诊断变成表演。
- ❌ **把诊断题当练习题讲**：诊断题的作用是定位，讲透会浪费 20 分钟，且用户会以为"学过了"。
- ❌ **出 10 道以上**：超过 5 道，完成率断崖式下降。
- ❌ **题目全来自第一章**：测不出真实水平，还会让有基础的用户觉得被冒犯。
- ❌ **判级语言带评价**：不说"你基础很差"，说"你在 X 上有缺口，我们从这里开始补"。
- ❌ **不回述结果直接开讲**：用户不知道系统记住了什么，下次还要重新说一遍。

## 什么时候可以跳过诊断

- 用户已经明确说"我是 XX 专业大二，学过 A/B/C，直接从 D 开始" → 听他的，记 `override`。
- 用户只要一道题的解法（`solve` 模式，没打算长期学）→ **不做诊断**，直接答题。诊断是给"要学一条路径"的人准备的，不要强加。
