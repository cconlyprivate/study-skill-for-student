# 教育技术学（educational-technology）

> 先读 `../../references/curriculum-rules.md`（难度与排序）与 `../../references/learning-card-template.md`（讲解结构）。
> 本文件只给这个专业的知识骨架与专业习惯。

## 1. 这个专业在训练什么

教技的人靠一份**别人能执行、证据能检验的设计**吃饭：把“学生要学会 X”拆成四件东西——可观察的目标、有认知依据的活动序列、匹配目标与条件的媒体资源、能收上证据的评价，再加一层承载它们的技术方案（平台、内容标准、数据）。四件缺一件，交付物就只是素材堆。

它和“会做课件、会剪微课、会修电脑、会开平台账号”不是一回事。软件只是表达工具，核心能力是**在课时、预算、教师可维护性与学习者起点的约束下做取舍，并说清为什么这样取舍**。

分界线：教育学问“人怎样学会、什么样的教与学关系成立”，教技接着问“用什么流程、资源与技术把它稳定落地，并且怎么证明它真的落地了”；计算机科学与技术问“这个问题能不能算、要付多少时间与空间代价”，教技问“这个技术在学习情境里值不值得上、会不会抬高认知负荷”。同一件事，教育学交论证，计科交实现，教技交方案与代价。

**最容易误解的一点**：以为教技 = 教育信息化里的设备与软件操作。真正拉开差距的是 K03（教学设计）与 K06（评价与评估）——能否把目标、活动、证据串成一条可检查的链，决定你交的是“方案”还是“素材”。

**最陡的三门课**：教学设计（目标、活动、评价三者必须同时成立，任何一处脱节都会当场暴露）、学习科学与技术（结论都有实验边界，凭感觉写会全错）、数字化学习环境与资源（标准与数据模型是硬约定，写错粒度就没有分析价值）。

## 3. 能力目标（毕业时能做的可检验的事）

1. 能把一句含糊的“学会 X”写成含对象、行为、条件、标准的目标，并定位到布鲁姆二维表的某一格。
2. 能为一个单元交出完整教学设计方案：ADDIE 每个阶段有产物，目标、活动、评价一一对应。
3. 能在给定课时、预算与平台条件下做媒体与技术选型，并写出“为什么不用另一个”的论证。
4. 能逐条指出一份课件违反的多媒体设计原则与认知负荷来源，并改到能讲清依据。
5. 能设计一份评价方案：形成性任务、量规、证据链，并说明分数怎么用、不能怎么用。
6. 能判断一个平台或标准方案是否满足需求，指出数据粒度、互操作与合规上的缺口。
7. 能组织一轮小规模可用性测试与试点，写出问题分级与下一轮修改。
8. 能用学习数据解释一个学习问题，同时说出该指标会被怎样误读。

## 5. 术语与符号约定

| 符号/术语 | 含义 | 单位/范围 | 本专业容易写错的地方 |
|---|---|---|---|
| 教育技术（AECT 定义） | 为促进学习与提高绩效而创造、使用、管理适当的技术过程与资源 | 过程与资源两条腿 | 只写工具与资源，漏掉“过程”；把教技等同于设备与信息化建设 |
| 教学设计（ID） | 用系统方法把学习目标转成可执行方案的过程 | 课程、单元、课时都可做 | 与“备课”混同：备课按内容组织，ID 必须先有目标与评价证据 |
| ADDIE | 分析、设计、开发、实施、评价五个阶段 | 循环，不是瀑布 | 把评价只放最后一步；形成性评价应贯穿每一步并可回溯 |
| Dick-Carey 模型 | 需求评估→目标→评价工具→策略→材料→形成性评价→总结性评价→修订 | 线性并带回路 | 与 ADDIE 混写：它把评价工具定在策略之前，顺序写反是硬错 |
| 前端分析 | 开课前的需求、学习者、任务、环境四类分析 | 四项缺一不可 | 只做学习者分析就当前端分析做完，漏任务与环境约束 |
| 学习目标 ABCD | 对象、行为、条件、程度 | 一条目标四要素 | 写“学生能感受技术之美”：无行为动词，第三方无法验收 |
| 行为动词（布鲁姆修订版） | 记忆、理解、应用、分析、评价、创造六级 | 由低到高，创造为顶 | ①把“理解”直接当行为动词，它不可观察，要落到解释、举例、比较；②把“综合”当第六级，修订版顶端是创造 |
| 二维分类 | 四类知识（事实、概念、程序、元认知）配六级过程 | 4 乘 6 共 24 格 | 只写过程维度漏知识维度；把程序性知识一律当“应用” |
| 教学事件（加涅） | 从引起注意到促进迁移的九个事件 | 一节课不必全用 | 当成必须九个都上的流程；它对应内部加工，可合并可省略 |
| 认知负荷 | 内在、外在、相关三类之和：$L = L_{\mathrm{int}} + L_{\mathrm{ext}} + L_{\mathrm{ger}}$ | 工作记忆约 $4 \pm 1$ 个组块 | 认为内容越少负荷越低；内在负荷由元素交互决定，删必要元素会破坏完整性 |
| 多媒体学习三假设 | 双通道、每通道容量有限、学习需主动选择组织整合 | 三条同时成立 | 只提双通道不提容量，就解释不了为什么加动画反而更差 |
| 冗余效应 | 同一信息以多种形式重复呈现而降低效果 | 与分裂注意效应不同 | 三条原则混着写；字幕对听障与非母语者是必要支持，必须写边界条件 |
| 模态 | 信息的呈现方式：视觉、听觉 | 与“媒体”不是一回事 | 把“用了视频”当多模态；视频只念稿，仍是单通道 |
| 媒体选择 | 按目标、学习者、条件、代价四要素选媒体 | 没有万能媒体 | 写“多媒体优于传统媒体”；媒体本身不产生学习，起作用的是一致的设计方法 |
| 视觉层级 | 对比、重复、对齐、亲密性四条排版原则 | 每页只留一个视觉焦点 | 把“装饰”当设计；颜色堆叠与对齐混乱会切断眼动路径 |
| 可访问性 | 文本对比度、替代文本、键盘可达 | 正文对比度不低于 $4.5:1$ | 只用颜色区分信息；图片不给替代文本，读屏器读到空白 |
| SCORM | 内容包规范：清单文件、可共享内容对象、运行环境接口 | 版本 1.2 与 2004 并存 | 以为它能记录任意学习行为；数据只到完成、得分、时长这一粒度 |
| xAPI | 主体—动词—对象语句，写入学习记录库 | 可脱离平台独立记录 | 与 SCORM 混用；它是事件流规范，不管内容打包与播放 |
| LTI | 工具与平台之间的互操作协议 | 与学习记录无关 | 把 LTI 当数据标准；它管能不能嵌进去用，不管学了多少 |
| 学习分析指标 | 完成率、交互次数、停留时长、测验轨迹 | 指标不等于构念 | 用停留时长当投入度；挂机也在累计，必须配交互与产出证据 |
| 形成性评价（两义） | ①教学中为改进教与学；②材料开发中的小规模试用 | 两义不能混用 | 把“多考几次”叫形成性；没有反馈与修改动作就不是 |
| 可用性测试 | 真实用户做任务，记录完成率、时间、错误、满意度 | 5 名用户能发现多数问题 | 与形成性评价混：一个测能不能用，一个测有没有学会 |
| SUS | 十题量表折算成百分制得分 | $0$–$100$ 分，68 约为平均 | 把 SUS 分当学习效果；它只反映主观可用性 |
| 出声思维 | 边做边说，主持人只追问不引导 | 需先演练再正式测 | 追问变成诱导（“这里是不是很难找”），数据被污染 |
| 量规 | 维度 × 水平，每格给描述语 | 常用 3 到 4 级 | 维度写成任务清单；水平描述用“较好、一般”这类无区分度的词 |
| 一致性（alignment） | 目标、活动、评价三者的对应关系 | 每条目标至少一份证据 | 活动很热闹却收不上证据；评价考了没教的内容 |

## 6. 典型题型与解题套路

### 教学设计方案题（给学情与内容，写一课时或一单元方案）
1. 先做前端分析并写进方案抬头：学习者起点、先备知识、可用课时与设备、教师能维护到什么程度。
2. 目标按“对象＋行为动词＋条件＋程度”写，每条只放一个动词，并标出它落在二维表的哪一格。
3. 评价先行：每条目标配一份能收上来的证据（一道题、一个作品、一次口头解释），再让活动只为产出这份证据服务。
4. 写活动序列时对齐加涅九事件，标出哪几件合并、哪几件省略，理由要落到学生起点。
5. 收尾补两段：媒体与资源清单（含替代方案），以及“如果这个班没达成，下一轮改哪一步”。
**常见失分点**：目标写成不可观察的素养口号，活动与评价各自为政，方案读起来是流程单而不是设计。

### 媒体选择与论证题（给目标与条件，问用什么媒体、为什么）
1. 把题干条件抄成四栏：目标类型、学习者特征、环境约束（带宽、设备、课时）、代价（开发工时、维护成本）。
2. 先用硬约束排除：没有网络就别谈在线协作，教师无法维护就别选自建平台。
3. 用认知负荷与多媒体原则论证取舍：说明所选媒体是否引入外在负荷，哪些设计原则必须遵守。
4. 给出一个备选方案并写“为什么放弃”，论证的价值全在这一段。
5. 写验收指标：用什么观察判断这个媒体真的起作用（不是“学生说喜欢”）。
**常见失分点**：只夸新技术，不写代价与备选，论证退化成产品介绍。

### 评价方案设计题（给一门课或一个项目，要求评价方案）
1. 先列“目标—证据”对照表，每条目标至少一份证据，缺证据的目标要么改目标要么改评价。
2. 划分形成性与终结性：形成性任务要写清反馈给谁、多久内反馈、反馈后改哪一步教学。
3. 为开放性任务写量规：维度来自目标而不是任务清单，水平数 3 到 4 级，每级给可判断的描述语。
4. 说明分数怎么用：达标判定与排序是两套解释，不能拿名次替代达标率。
5. 补数据与伦理：采集哪些行为数据、存在哪里、谁能看、家长与学生是否知情。
**常见失分点**：只写考试与作业清单，没有证据链和反馈回路，方案落不了地。

### 技术方案分析题（给一个平台、标准或系统方案，要求评估）
1. 拆需求与干系人：教学管理者、教师、学生、技术支持各自要什么，先标出相互冲突的那一条。
2. 对齐标准与数据粒度：内容用 SCORM 还是 xAPI，工具接入用 LTI，逐条写明这个方案能记录什么、记不到什么。
3. 算代价：开发与迁移工时、培训成本、后续维护由谁承担，给出量级而不是“较高”。
4. 查可用性与可访问性：关键任务能不能在三次点击内完成，对比度、替代文本、移动端是否达标。
5. 给试点与验收指标：先小范围跑一轮，用完成率、任务时间、错误数、SUS 判断是否推广。
**常见失分点**：只谈功能清单，不谈数据粒度与维护成本，结论无法支撑采购或上线决策。

## 7. 常见误区

1. **把教技当“做课件、修电脑”** → 错在交付物认知；应把成品定义成“目标—活动—媒体—评价”四件套加一份可验收的设计说明。
2. **先做材料再补目标** → 错在顺序倒了；应从目标与证据倒推活动与媒体，材料只为目标服务。
3. **目标写“培养信息素养、感受技术之美”** → 错在没有可观察动词；应换成“能给定三个学习网站各写一条评价标准”这类可验收表述。
4. **媒体越新越好、动画越多越好** → 错在忽略外在负荷与冗余效应；应先用四要素选型，再用分段、信号、一致性原则逐条压负荷。
5. **把“多考几次”当形成性评价** → 错在缺反馈回路；应规定每类任务反馈给谁、多久内改哪一步教学，并留下改动记录。
6. **用 SCORM 包做学习分析** → 错在数据粒度不够；应改用 xAPI 语句记录关键事件，并写清学习记录库的归属与权限。
7. **可用性测试找同事点两下** → 错在既不是目标用户也不布置任务；应写五个任务脚本，记完成率、时间、错误与出声思维原话。
8. **把学习时长当学习投入** → 错在挂机也计时；应至少两个指标交叉验证，并配交互与产出证据。

## 9. 交叉专业与后续方向

- **和教育学的区别**：教育学答“为什么这样教、凭什么说它有效”，产出是目标体系、学习理论依据、研究设计与测量证据；教技答“用什么流程、资源、平台与评价工具把它做出来并跑起来”，产出是设计方案、资源包、平台与数据方案、验收指标。教育学可以停在“应该这样教”，教技必须交出“下周就能上线”的版本和它的代价。
- **和计算机科学与技术的区别**：计科问“能不能算、时间与空间代价多少、系统怎么不崩”，硬约束是复杂度、并发与可靠性；教技问“这个技术在学习情境里值不值得上、会不会抬高认知负荷、数据能不能支撑教学决策”，硬约束是课时、学习者、教师可维护性与预算。教技会用接口、数据库与前端框架，但目标是选型与集成，不是自研底层。
- **和学习科学、心理学的区别**：它们问机制（人怎样学、什么条件下迁移），教技问落地（在真实课堂与平台里怎么设计、怎么验证），机制只是设计的依据而不是交付物。
- **和信息管理与信息系统的区别**：信管把业务流程变成系统，教技把学习过程变成可设计、可评价、可分析的教学系统，核心资产是学习证据而不是业务单据。
- **后续方向**：考研可走教育技术学学硕、现代教育技术（教育硕士）、学习科学与技术方向；岗位集中在教学设计师、企业培训与在线课程开发、教育产品与学习体验设计、教育数据分析、高校与中小学教育技术中心；进阶课程是学习分析、人工智能教育应用、游戏化学习与教育产品设计。
