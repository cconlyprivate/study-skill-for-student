# 计算机科学与技术（computer-science）

> 先读 `../../references/curriculum-rules.md`（难度与排序）与 `../../references/learning-card-template.md`（讲解结构）。
> 本文件只给这个专业的知识骨架与专业习惯。

## 1. 这个专业在训练什么

把混乱的现实问题**抽象成可计算的形式**，然后回答两个问题：能不能算得出来（正确性）、要花多少代价（时间与空间）。

它和"会写代码"不是一回事。写代码是表达手段，核心能力是**在约束下选择数据结构与算法，并知道代价**。

**最容易误解的一点**：以为计科 = 编程。实际上编程只是 K01，真正拉开差距的是 K03（算法）、K05（系统）、K06（网络）——这三块决定你能不能解释"为什么这样写会慢/会崩"。

## 2. 课程地图

| 学期 | 课程 | 模块 | 先修 | 难度感受 |

| 大一下 | 数据结构 | K02 | K01 | 转折点：从"能跑"到"跑得动" |
| 大二上 | 计算机组成原理 | K04 | K01 | 抽象层突然落地到电路，很多人第一次听不懂 |
| 大二下 | 算法设计与分析 | K03 | K02 | 分治/DP/图，是最拉开差距的一门 |
| 大二下 | 操作系统 | K05 | K04、K02 | 概念多但要靠"机制 + 为什么这样设计"串起来 |
| 大三上 | 计算机网络 | K06 | K05 | 协议细节多，建议自顶向下学 |
| 大三上 | 数据库系统 | K07 | K02 | SQL 容易，索引与事务才见功力 |
| 大三下 | 软件工程 | K08 | K02、K07 | 偏方法与协作，工程性 > 技术性 |

**最陡的三门课**：算法（因为需要"想出"而不只是"记住"）、操作系统（因为要同时在抽象与硬件两层思考）、组成原理（因为要建立"指令 → 电路 → 时钟"的因果链）。

## 3. 能力目标（毕业时能做的可检验的事）

1. 能用一段话把一个模糊需求拆成"输入—输出—约束"，并选出合适的数据结构。
2. 能对给定代码判断时间/空间复杂度，并说明最坏情况出现在什么输入上。
3. 能解释一段程序从源代码到 CPU 执行经历了什么（编译、链接、装载、页表、缓存）。
4. 能定位"程序变慢/内存涨了/连接超时"的层次归属（算法、OS、网络、DB、应用）。
5. 能为一个功能设计表结构与索引，并写出能走索引的 SQL。
6. 能读懂并修改 5000 行级别的他人代码，写出可复现的 bug 报告。
7. 能用测试用例（含边界）证明自己的实现是对的，而不只是"跑通了样例"。

## 5. 术语与符号约定

| 符号/术语 | 含义 | 单位/范围 | 本专业容易写错的地方 |
|---|---|---|---|
| `n` | 输入规模 | 元素个数/顶点数，按语境 | 图算法里 `n` 顶点、`m` 或 `e` 边，别混用 |
| `O(f(n))` | 渐进上界 | 忽略常数与低阶 | `O(2n)` 要写成 `O(n)`；`O(n+m)` 不能简化成 `O(n)` |
| `Θ(f(n))` | 紧确界 | — | 说"快排是 O(n log n)"是不严谨的，最坏是 O(n²) |
| `T(n)` | 递归式 | — | 写递归式时别漏 base case |
| 下标 | 数组/字符串位置 | C 系从 0 开始 | 教材伪代码常用 1 起始，抄的时候会差 1 |
| 指针 `p` / `*p` | 地址 / 解引用 | — | `p->next` 与 `(*p).next` 等价；`*p++` 的优先级常错 |
| 栈顶 `top` | 下一个可写位置或当前栈顶 | 两种约定不能混 | 判断空/满的条件随约定变化 |
| 队头 `front` / 队尾 `rear` | 循环队列 | 取模 `%n` | "牺牲一个单元"判满与"计数器"判满公式不同 |
| 补码 | 负数表示 | n 位范围 −2^(n−1) ~ 2^(n−1)−1 | 取反加一别忘加一；最小值取负会溢出 |
| IEEE 754 | 浮点表示 | 单精度 1+8+23 | `0.1+0.2 != 0.3`，比较要设 epsilon |
| 大端/小端 | 字节序 | — | 网络字节序是大端，主机常是小端 |
| 逻辑地址/物理地址 | 页表翻译前后 | 页大小通常 4KB | 页内偏移位数 = log2(页大小) |
| TLB | 页表缓存 | — | TLB 命中 ≠ 缓存命中，两层别混 |
| 上下文 | 寄存器 + PC + 栈指针 | — | 线程切换不换页表，进程切换换 |
| P/V 或 wait/signal | 信号量操作 | 信号量 ≥ 0 | `P` 减、`V` 加；顺序写反会死锁 |
| 死锁四条件 | 互斥、占有并等待、不可抢占、循环等待 | — | 破坏任意一个即可预防，但代价不同 |
| 局部性 | 时间/空间局部性 | — | 解释缓存命中率必须说清是哪种局部性 |
| 命中率 `h` | 缓存命中比例 | 0–1 | 平均访问时间 = h·t_c + (1−h)·t_m，别漏 miss penalty |
| ACID | 原子/一致/隔离/持久 | — | 隔离性靠锁或 MVCC，不是"数据库自动保证"这么含糊 |
| 隔离级别 | RU/RC/RR/SERIALIZABLE | — | MySQL 默认 RR，且用间隙锁防幻读，和标准不同 |
| 1NF/2NF/3NF/BCNF | 范式 | — | 2NF 针对复合主键的部分依赖，单主键表天然满足 |
| 扇出 `f` | B+ 树每个结点子指针数 | — | 树高 ≈ log_f(N)，估算题必用 |
| `RTT` / `MSS` / `cwnd` | 往返时延 / 最大段 / 拥塞窗口 | ms / 字节 / 字节 | 吞吐 ≈ cwnd/RTT，单位别错 |

## 6. 典型题型与解题套路

### 计算题（复杂度、地址翻译、调度、吞吐）
1. 先写清已知量并统一单位（B vs b、ms vs s）。
2. 写出公式，再代数；**先符号后数值**，避免中间四舍五入。
3. 算完做量级检查：命中率该在 0–1、利用率不该 > 100%。
**常见失分点**：把 `Mbps` 当 `MB/s`；把页内偏移算成页号。

### 证明题（正确性、复杂度下界）
1. 先写"要证什么"，把结论改写成"存在/对任意"的形式。
2. 选工具：循环不变式（迭代）、数学归纳（递归）、交换论证（贪心）、反证（下界）。
3. 写出不变式的**初始化、保持、终止**三段，缺一段就不完整。
**常见失分点**：只证"算法能跑"，没证"答案最优"。

### 编程题
1. 先说清输入输出、边界（空、单元素、重复、极值）、是否需要原地。
2. 写伪代码 → 确认复杂度 → 再写代码。
3. 用 3 组用例手跑：正常、边界、退化。
**常见失分点**：不处理空输入；递归忘 base case；用 `int` 存会溢出的和。

### 简答/对比题（进程 vs 线程、TCP vs UDP）
1. 先给一句"本质区别"（资源分配单位 vs 调度单位）。
2. 再列 3 个维度对比（开销、通信、隔离性）。
3. 最后给一个"什么时候选哪个"的场景。
**常见失分点**：只背定义，不给场景，拿不到采分点。

### 设计题（表结构、缓存、接口）
1. 先写访问模式（读多还是写多、QPS、数据量级）。
2. 再定结构（表/索引/缓存键），并说明为什么不是另一种。
3. 最后说一个"出问题时怎么发现"（监控指标）。
**常见失分点**：一上来画架构图，不说约束。

## 7. 常见误区

1. **代码跑通样例就认为对了** → 错在没测边界；正确做法是先列空/单元素/极值三组用例再写代码。
2. **说"快排 O(n log n)"** → 错在漏了最坏情况；应说"平均 O(n log n)，最坏 O(n²)，可通过随机化避免"。
3. **把并发当并行** → 错在混淆"交替执行"与"同时执行"；并发是结构，并行是硬件能力。
4. **认为 TCP 保证"一定送达"** → 错在把"可靠"理解成"必达"；它保证的是"要么有序送达，要么明确报错"，且连接可能断。
5. **索引越多越好** → 错在忽略写入放大与优化器选择成本；每个索引都在为写操作付费。
6. **背 SQL 语法不看执行计划** → 错在不知道 `WHERE` 里对列做函数会让索引失效。

## 9. 交叉专业与后续方向

- **和软件工程的区别**：计科问"能不能算、代价多少"，软工问"这个系统怎么在需求变化中活得久"。同一道题，计科答复杂度，软工答可维护性。
- **和电子信息工程的区别**：计科从"指令集"往上，电子从"信号与电路"往下；交汇点是组成原理与嵌入式。
- **和数学的区别**：数学要最一般的证明，计科要"在多项式时间内能算"的构造。
- **后续方向**：分布式系统、编译原理、机器学习系统、数据库内核、系统安全；考研常考 408（数据结构/组成/OS/网络）。
